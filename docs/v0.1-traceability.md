# v0.1 release traceability

Maintainer-facing map from the v0.1 contract in
[#1](https://github.com/photon-circus/ph-surfaces/issues/1) to its durable
evidence. The public contract lives in the [README](../README.md) and crate
documentation; this file does not restate it in full.

Release mechanics such as versioning, publication, provenance, and tagging are
covered by [`RELEASING.md`](../RELEASING.md). This repository document is not
included in the packaged crate.

## Contract evidence

| Contract area | Primary implementation | Independent or public evidence | CI checks |
| --- | --- | --- | --- |
| Static representation and construction invariants | `src/surface.rs` | `BilinearSurface` compile-fail doctests and unit tests | `test`, `doc` |
| Boundary policy, clamping without extrapolation, and X-first error precedence | `src/lookup.rs`, `src/boundary.rs`, `src/error.rs` | `tests/conformance/boundary.rs` | `test` |
| Integer interpolation, ties away from zero, and arithmetic bounds | `src/interp.rs` | `tests/conformance/reference.rs`, `scalar.rs`, and `range.rs` | `test`, `integer only` |
| Normative X-then-Y evaluation order | `src/evaluate.rs` | `tests/conformance/order.rs` | `test`, `release test` |
| Linear, Binary, Uniform, and Bucketed per-axis lookup | `src/axis/` | `tests/conformance/lookup.rs` and `strategies.rs` | `test`, `release test`, `doc` |
| Strategy-independent values, errors, rounding, and boundary behaviour | Shared path in `src/evaluate.rs` and `src/lookup.rs` | Black-box conformance suite and all sixteen pairings in `tools/consumer` | `test`, `package consumer` |
| Exact referenced payload and bounded operation structure | Public cost constants and tests in `src/surface.rs`, `src/axis/`, and `src/lookup.rs` | README resource accounting and `examples/firmware_cost_budget.rs` | `test`, `examples`, `code size snapshot` |
| Stateless, allocation-free runtime | Unconditional `#![no_std]`, no dependencies, no runtime mutation or cache | Determinism conformance tests and downstream `#![no_std]` consumer | `no_std unconditional`, `integer only`, both core-only target checks |

The conformance suite uses only the public API. Its expected values come from
the independent `i128` reference in `tests/conformance/reference.rs` or from
hand calculations recorded in test comments; it does not use production
lookup code, floating point, or `ph-curves` as an oracle.

## Acceptance summary

The v0.1 implementation provides:

- unconditional `no_std`, core-only, allocation-free, integer-only runtime
  code with no dependencies or `unsafe`;
- validated static `u16 × u16 → i32` surfaces with explicit Error or Clamp
  behaviour on each side;
- one rounding policy and one observable X-then-Y composition order;
- four sealed lookup strategies selected independently per axis at compile
  time, with no runtime strategy discriminant;
- black-box conformance coverage for numerical, boundary, full-range, and
  cross-strategy behaviour;
- exact referenced-storage formulas and operation-structure bounds without
  presenting them as total memory, cycle counts, or WCET; and
- package inspection plus host, ordinary embedded, and core-only downstream
  build evidence.

The authoritative verification command is:

```sh
cargo xtask ci
```

A `SKIP` is not a pass. Release evidence requires the complete release profile
and a reviewed dated nightly as specified in [`RELEASING.md`](../RELEASING.md).

## Limits of the evidence

The evidence does not claim support for targets beyond the host and the two
named bare-metal targets. It also does not claim device accuracy, exhaustive
coverage of the full `u16 × u16` coordinate space, total RAM or flash, cycle
counts, or WCET. The committed size and assembly snapshots are non-normative
compiler-output records, not API guarantees.
